# astrocalendar-month

**Генератор ежемесячного астрономического календаря для канала [AstroAlert](https://t.me/astroalert_space) —
в его формате и с независимой проверкой каждого значения.**

Календарь не переписывается из готовых списков: всё считается заново по
эфемеридам JPL, каталогам Hipparcos и OpenNGC, орбитальным элементам MPC и
лентам предсказаний IOTA, а ключевые величины сверяются с JPL Horizons. На
выходе — готовый текст поста, протокол расчётов и QA-отчёт, отвечающий на
вопрос «можно ли это публиковать».

Проект сделан как инструмент для подготовки выпусков AstroAlert и проверен на
двух реальных выпусках канала — за август и сентябрь 2026 года. Он не является
официальным продуктом канала: это внешний расчётный конвейер, автор канала к
его разработке отношения не имеет.

Пример выдачи — в [`examples/`](examples/): пост, протокол и QA-отчёт за
сентябрь 2026.

Разбор задачи, варианты реализации и оценка трудозатрат — в [ANALYSIS.md](ANALYSIS.md).

## Что умеет

Каждая строка ниже — реальная выдача генератора за сентябрь 2026.

**Луна: фазы, перигей и апогей, сближения с планетами, звёздами и объектами каталогов**

```
▪️04 сентября, 11:00 — Луна в фазе последней четверти в созвездии Телец
▪️07 сентября, 00:00 — Луна (Ф=-0,22) в перигее своей орбиты на расстоянии 368228 км от Земли
▪️08 сентября, 09:00 — Луна (Ф=-0,11) проходит в 0°42′ севернее рассеянного скопления M44 ("Beehive") (V=+3,1m) в созвездии Рак
```

**Покрытия планет и звёзд Луной — с полосой видимости, посчитанной по всей Земле**

```
▪️14 сентября, 14:35 — Покрытие Венеры (V=-4,8m) Луной (Ф=+0,12) видимое в Калининградской области, на Кавказе и на Юге Европейской части России, дневное небо
▪️08 сентября, 21:44 — Покрытие Юпитера (V=-1,8m) Луной (Ф=-0,07) видимое на Таймыре, в Якутии и на Новой Земле и в российской Арктике
```

**Затмения Солнца и Луны** — полосы полной и частных фаз, момент наибольшего
затмения, контакты теневой фазы и откуда их реально видно.

```
▪️12 августа, 20:46 — Полное солнечное затмение, полоса полной фазы проходит через Таймыр, Гренландия и Исландия, Арктика, Европа, частные фазы видны в Калининградской области, на Новой Земле и в российской Арктике и на Северо-Западе России
```

**Планеты: стояния, противостояния, соединения, элонгации, максимальный блеск, тесные пары**

```
▪️10 сентября, 21:00 — Уран переходит от прямого движения к попятному
▪️26 сентября, 05:00 — Нептун (V=+7,7m) в противостоянии с Солнцем в созвездии Рыбы
▪️24 сентября, 20:00 — Венера в максимальном блеске (V=-4,8m) в созвездии Дева
```

**Периоды видимости планет** — начало и окончание утренней и вечерней
видимости, с требованием устойчивости критерия трое суток подряд.

**Спутники планет** — конфигурации галилеевых спутников и положение Титана.

```
▪️04 сентября, 04:00 — Все 4 Галилеевы спутника окажутся западнее Юпитера (V=-1,8m)
▪️06 сентября, 21:00 — Спутник Титан (V=+8,4m) расположен севернее Сатурна (V=+0,5m) в созвездии Кит
```

**Кометы** — отбор по блеску из всего каталога MPC и автоматический поиск
сближений со звёздами Hipparcos и объектами OpenNGC.

```
▪️23 сентября, 21:00 — Комета 161P/Hartley-IRAS (V=+12,7m) проходит в 0°49′ западнее планетарной туманности NGC 246 (V=+10,9m) в созвездии Кит
```

**Астероиды** — проходы ярких малых планет у звёзд и туманностей, тесные
пролёты околоземных объектов и **покрытия звёзд астероидами** с пересчётом
полосы по актуальной орбите.

```
▪️29 августа, 00:18 — Астероид (14717) 2000 CJ82 покрывает звезду HIP 20901 (V=+5,0m), падение блеска 13,9ᵐ, полоса проходит через Центр Европейской части России, Урал, Западная Сибирь, Восточная Сибирь
```

**Метеорные потоки** — момент максимума по солнечной долготе λ☉ из таблиц IMO.

**Космонавтика** — пуски со статусом из Launch Library 2, периоды видимости
МКС и китайской станции.

## Быстрый старт

```bash
git clone https://github.com/wwwparser/astrocalendar-month.git
cd astrocalendar-month
pip install -r requirements.txt
```

Скачать эфемериды (один раз, ~85 МБ):

```bash
curl -L -o data/de440s.bsp   https://ssd.jpl.nasa.gov/ftp/eph/planets/bsp/de440s.bsp
curl -L -o data/jup380s.bsp  https://ssd.jpl.nasa.gov/ftp/eph/satellites/bsp/jup380s.bsp
```

Собрать календарь:

```bash
python scripts/build_calendar.py 2026 9
```

Всё остальное — каталоги Hipparcos и OpenNGC, элементы комет MPC, ленты
предсказаний покрытий, TLE станций, ответы Horizons, CNEOS и Launch Library —
скачивается автоматически при первом запуске и кэшируется в `data/cache/`.
Первый прогон занимает 10–15 минут, последующие — 3–5.

## Команды

### Собрать календарь

```bash
python scripts/build_calendar.py                        # месяц из config.py
python scripts/build_calendar.py 2026 9                 # конкретный месяц
python scripts/build_calendar.py 2026 9 --no-horizons   # без сетевой сверки, быстрее
python scripts/build_calendar.py 2026 9 --all-ranks     # опубликовать всё рассчитанное
```

### Опубликовать в Телеграм

```bash
python scripts/publish_telegram.py 2026 9           # предпросмотр, ничего не отправляет
python scripts/publish_telegram.py 2026 9 --send    # отправить в канал
```

Без `--send` скрипт только показывает текст: публикация необратима. Токен бота
и id канала берутся из `.env` (шаблон — `.env.example`), в код они не попадают.
Пост длиннее 4096 символов режется по строкам, а не посередине.

### Черновик расписания пусков

```bash
python scripts/collect_launches.py 2026 9
```

Кладёт рядом `data/spaceflight_YYYY-MM.auto.json` со статусами Launch Library 2
и **не трогает** основной файл. Нужные строки переносятся руками.

### Точные времена пролётов станций

```bash
python scripts/refresh_passes.py 3      # ближайшие 3 суток
```

Запускается за 2–3 суток до события: месячная сборка называет только период,
потому что элементы орбиты к дате публикации устаревают.

## Работа над выпуском: пошагово

**1. Космонавтика.** Получить черновик пусков и перенести нужное в
`data/spaceflight_YYYY-MM.json`, поправив формулировки и поставив
`include: true`. Без подтверждённого источника событие в календарь не идёт —
это единственный слой, который не считается.

```json
{
  "when_msk": "2026-09-09 19:15",
  "text": "Запуск космического корабля \"Прогресс МС-35\" ...",
  "include": true,
  "confidence": "высокая",
  "sources": ["Launch Library 2: net 2026-09-09T16:15:03Z, статус Go"]
}
```

**2. Собрать календарь.** Если в конце появилось
`ВНИМАНИЕ: есть события с флагом REVIEW` — сначала смотреть QA-отчёт.

**3. Прочитать QA-отчёт** `out/QA_REPORT_YYYY-MM.md`: флаги REVIEW, раздел
«Проверка на пропуски», события с уверенностью «средняя» и «низкая».

**4. Пересчитать пролёты станций** за 2–3 дня до публикации.

**5. Опубликовать.**

Опционально: чужой календарь для сверки кладётся в
`data/source_list_YYYY-MM.json`, внешний контрольный — в
`data/external_YYYY-MM.json`, свои выводы — в `data/notes_YYYY-MM.md`. Все три
файла автоматически попадают в протокол и QA-отчёт.

## Файлы на выходе

| файл | что внутри | кому |
|---|---|---|
| `out/calendar_YYYY-MM.txt` | готовый пост | копируется в Телеграм как есть |
| `out/protocol_YYYY-MM.md` | построчный разбор: расчёт, источники, уверенность; полосы покрытий и затмений; что из космонавтики не вошло и почему | автору выпуска |
| `out/QA_REPORT_YYYY-MM.md` | сводка по рангам, матрица «чем считается / чем проверяется», флаги REVIEW, сверка с Horizons, provenance, сроки годности данных, проверка на пропуски | перед публикацией |

## Что попадает в пост, а что нет

У каждого события есть ранг редакционной значимости — иначе технически верный
проход Цереры в 1,8° от скопления вытесняет из поста затмение.

| ранг | что это | в пост |
|---|---|---|
| `must` | затмения, фазы Луны, покрытия планет, противостояния, элонгации, пуски | да |
| `interesting` | соединения, конфигурации спутников, покрытия звёзд, кометы у ярких объектов | да |
| `optional` | верно, но узко: слабые сближения, астероиды у скоплений | нет |
| `technical` | низкая уверенность, требует пересчёта ближе к дате | нет |

Сентябрь 2026: рассчитано 71 событие, в пост отобрано 48 (11 `must` +
37 `interesting`). Правила — в `src/astrocal/rating.py`.

## Как это устроено технически

Конвейер из четырёх слоёв. Ключевая идея: **слои различаются по
воспроизводимости**, и смешивать их в одном списке без пометок нельзя.

```
эфемериды и каталоги        расписания и ленты
   (детерминированно)        (стареют за дни)
          │                          │
          ▼                          ▼
   модули events/*  ──────────────────
          │
          ▼
   единый список Event  ──▶  rating.py    ранг значимости
          │                  qa.py        проверки, флаги REVIEW
          │                  verify.py    второй источник — Horizons
          ▼
   calendar.txt · protocol.md · QA_REPORT.md
```

**Ядро.** [Skyfield](https://rhodesmill.org/skyfield/) поверх JPL DE440s.
Каждое явление — это либо ноль функции, либо её экстремум на сетке времени:
соединение — минимум углового расстояния, стояние — ноль скорости по
эклиптической долготе, противостояние — переход разности долгот через 180°.
Грубая сетка находит интервал, дальше золотое сечение или бисекция уточняют
момент до секунды (`core.py`).

**Покрытия и затмения** считаются одной геометрией. Наблюдатель видит покрытие,
когда угол между направлениями на Луну и на объект меньше видимого радиуса
лунного диска. Узлы регулярной сетки 2° по всей Земле переводятся из ITRS в
ICRF матрицей вращения Земли, дальше всё считается векторно в numpy — Skyfield
вызывается один раз на весь массив времён, а не на каждую площадку. Отсюда
полоса видимости и её пересечение с регионами (`occultations.py`, `eclipses.py`,
`geo.py`). Солнечное затмение — та же задача, только с двумя полосами: полной
и частной фазы.

**Покрытие звезды астероидом** — тот же цилиндр тени, но лучи звезды
параллельны. Ось тени пересекается с эллипсоидом WGS-84 аналитически, и её
след даёт центральную линию (`asteroid_occultations.py`). Кандидатов берём из
ленты IOTA, а полосу считаем сами по свежей орбите: годовая лента считается
один раз и устаревает — у покрытия HIP 20901 астероидом (14717) расхождение
достигает 20 часов.

**Кросс-матч** комет и астероидов с каталогами: трек объекта на сетке 15 минут,
векторное расстояние гаверсинусом до всех подходящих объектов Hipparcos и
OpenNGC, локальные минимумы, уточнение момента и дедупликация — одно сближение
даёт одну строку, а не двадцать (`comets.py`, `asteroids.py`).

**Наблюдаемость.** Момент математического минимума часто приходится на светлое
время или на период под горизонтом. Событие сдвигается к ближайшему моменту,
когда картинку реально видно из России, при условии что сближение к тому
времени ещё в силе; в протокол пишутся оба времени.

**Слой расписаний** изолирован. Космонавтика читается из JSON, где у каждой
записи обязательны источник и флаг `include`. Пролёты станций считаются по TLE
и SGP4, но точное время публикуется только при возрасте элементов не больше
трёх суток — иначе календарь называет период.

**Проверка** — отдельный слой поверх готового списка: `verify.py` сверяет
положения с JPL Horizons, `qa.py` прогоняет sanity-проверки и расставляет флаги,
`rating.py` решает, что вообще показывать читателю.

Всё сетевое кэшируется в `data/cache/`, поэтому повторный прогон месяца не
требует интернета (кроме опциональной сверки).

## Как устроена проверка

**Второй источник.** `verify.py` независимо запрашивает у JPL Horizons видимые
координаты тел — в системе истинного экватора и равноденствия даты, на тот же
момент — и сравнивает с локальным расчётом по DE440s. На сентябре 2026
наибольшее расхождение **0,10″** при допуске 1″.

**Автоматические проверки** (`qa.py`): часовой пояс и попадание в месяц,
физическая достижимость расстояний, соответствие расстояния до Луны пересчёту
на тот же момент, диапазоны блеска планет, существование созвездия, дубликаты,
формат строки. Всё непройденное попадает в QA-отчёт флагом `REVIEW` или `WARN`.

Проверка «расстояние против эфемериды» ловит именно тот класс ошибок, который
диапазонная проверка пропускает: 359 077 км — вполне правдоподобный перигей,
но не тот, что был 10 августа 2026 (правильный — 363 265 км).

**Проверка на пропуски.** `data/external_YYYY-MM.json` содержит независимый
внешний календарь, и отчёт показывает, чего у нас нет. Сентябрь 2026: из 28
внешних позиций совпали 22, остальные 6 не публикуются осознанно — с указанием
причины.

**Provenance.** У каждого события проставлены источник эфемерид, каталоги,
шкала времени и момент расчёта; у событий по TLE — возраст элементов и признак
того, публиковалось ли точное время.

## Настройка

`src/astrocal/config.py`:

- `SITE_LAT` / `SITE_LON` и `SOUTH_LAT` / `SOUTH_LON` — две площадки, по которым
  проверяется наблюдаемость: Москва и юг Европейской части. Вторая нужна, потому
  что объекты южнее −20° по склонению из Москвы не поднимаются;
- `COMET_MAG_LIMIT` — порог блеска для автоматического отбора комет;
- `APPROACH_LIMIT_DEG`, `STAR_MAG_LIMIT`, `DSO_MAG_LIMIT` — что считать
  интересным сближением;
- `COMET_STEP_MINUTES` — шаг трассировки кометы.

Правила отбора: `interesting()` в `events/comets.py` и `events/asteroids.py`,
ранги — в `rating.py`.

## Ограничения, о которых надо знать

- **Пролёты станций.** Прогноз по TLE точен трое суток. Месячная сборка поэтому
  называет период, а не минуту.
- **Блеск комет.** MPC и Horizons расходятся между собой на 1–2 величины, а с
  наблюдательными оценками — до 5. В календаре стоит значение MPC, обе оценки
  попадают в протокол.
- **Полоса покрытия звезды астероидом** считается по актуальной орбите, но
  собственной оценки ошибки у расчёта нет: σ берётся из ленты IOTA, и отчёт
  показывает, что остаётся от полосы при сдвиге на ±σ.
- **Начало видимости планеты** — редакционный критерий, а не физическая
  граница. Сдвиг порога на пару градусов двигает дату на 3–5 суток.
- **Стыковки и расстыковки** структурированного источника не имеют и
  заполняются вручную.
